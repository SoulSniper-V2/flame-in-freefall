1. Introduction
The purpose of this report is to describe the data acquired for ACME’s s-Flame experiment to facilitate its
analysis. The data is all digital, where the fuel was gaseous and there was no collection of soot or the
combustion gases. For each test, the key data consists of image files and a file with the non-imaging
measurements. Additional files such as chamber calculator output, camera metadata, and operational
logs provide information that can support the analysis.

It is recommended that readers interested in analyzing the s-Flame data begin by familiarizing themselves
with the hardware and instrumentation, either through the overview in the s-Flame Final Report or the
more comprehensive description found in the ACME Engineering Implementation document.

Those seeking to analyze the data should next review this document. To interpret the non-imaging data,
it is suggested that a sample data file be opened, named for example 19254A1_data.csv, which has
comma-separated values and can be opened with spreadsheet software such as Microsoft Excel. The data
is in raw voltages, where conversion to engineering units requires study of ACME’s Software Interface
Design Description, i.e., ACME-DOC-010 (where the latest version at the time of this writing is revision D).
Additional documents that may be important include:

2. s-Flame Overview
This text is the “Overview” from the ACME/s-Flame Final Report, which provides descriptions of the science,
preliminary results, and more. It is suggested that it be reviewed by those interested in analyzing the s-
Flame data.

The Structure and Response of Spherical Diffusion Flames (s-Flame) experiment is one of six independent
experiments that make up the Advanced Combustion via Microgravity Experiments (ACME) project for
which tests are conducted within the Combustion Integrated Rack (CIR) on the International Space Station
(ISS).

The experiment’s Principal Investigator (PI) is Prof. Chung K. Law of Princeton University. The experiment
has two Co-Investigators (Co-Is), namely Prof. Stephen D. Tse of Rutgers University and Dr. Kurt R.
Sacksteder of the NASA Glenn Research Center. While Sacksteder was actively engaged in defining the
experiment, he had transitioned to other NASA work long before the spaceflight operations limiting his
overall contributions.

Meanwhile, Dennis P. Stocker of the NASA Glenn Research Center is the Project Scientist (PS) for ACME
including s-Flame and the rest of the ACME investigations. In preparatory drop testing, etc., Dr. Fumiaki
Takahashi of the Case Western Reserve University (CWRU) served as the Deputy Project Scientist. For
ACME’s spaceflight operations, the NASA science team includes Drs. Vedha Nayagam and Uday G. Hegde
who are also with CWRU.

The s-Flames operations were conducted in two rounds of testing during Increments 60-63, where there
was no testing during Increment 62 due to limited crew availability. More specifically, the first round of
testing was conducted from Sept. 2019 to Jan. 2020, while the second-round testing – featuring helium
rather than nitrogen dilution - occurred from May to July 2020.



3. Tests Conducted
This text is an excerpt from the “Results” section of the ACME/s-Flame – 30-Day Operation
Accomplishments Report for ISS Increment 63 (which is included in the ACME/s-Flame Final Report).

        A total of 276 flames were ignited for the s-Flame experiment, with 29, 116, and 131 respectively
        ignited during Increments 60, 61, and 63. These numbers neglect some flames which quenched
        promptly after ignition. In this regard, science testing began at the end of Increment 60 and the
        first round of tests were completed during Increment 61. No tests were conducted in Increment
        62 due to a lack of crew time, where the second round of tests were fully conducted during
        Increment 63.

       The tests were conducted in two rounds, where the first was conducted in increments 60 and 61
       featured 145 flames (nominally) in which the fuel and oxygen (i.e., in the chamber atmosphere)
       were diluted with nitrogen. The second round conducted in increment 63 featured 131 flames
       (nominally) in which the fuel and oxygen were instead diluted with helium.
       The s-Flame experiment does not have living subjects like a life science experiment, but the tests
       are independently conducted with various gaseous fuels, including hydrogen, methane,
       hydrogen/methane blends, and ethylene. These are simple hydrocarbon gases for which the
       chemistry is relatively well understood.

       No samples (e.g., of soot) were collected for s-Flame; all of the ISS results were electronically
       transmitted to the ground. That is furthermore the case for all currently planned ACME
       experiments.

4. Data Interpretation
This key section provides (1) a general description of the raw experimental data and associated files and
(2) guidance on data conversions, e.g., to engineering units. Only limited guidance is provided for the
processing of image data, with the important exception of the conversion of the ACME DataCam images
from the raw Halcon object (HOBJ) format.

   A. Non-Imaging Data
       Data and files discussed in this section include the following:
          Data Output File
          Mass Flow Controller (MFC) Setpoint File
          Gas Chromatograph Instrumentation Package (GCIP) data
          Space Acceleration Measurement System (SAMS) data

       1. Data Output File
          The basic ACME non-imaging measurements for each test are together in a file described in
          Section 8.1 Data Output File on page 124 of Software Interface Design Description (ACME-
          DOC-010 Rev D). The test number is made up of the year (2-digts), day of year (3 digits), and
          test (a letter and single-digit number). As such, the example, 19254A1 is test A1 conducted
          on the 254th day of 2019. But the test could also be early on the next (e.g., 255th) day because
          the day portion of ACME test numbers is not changed when operations continue past
          midnight (whether GMT or Eastern) into the start of the next day.

           Tests numbers that only differ by the final digit (e.g., 19254H1, 19254H2, and 19254H3) are
           normally similar and occasionally identical, where the number is indicative of the variant or
           repeat. Letters I and O are not used because of their similarity to 1 and 0. While initially used
           in ACME testing, the letter E ceased to be used because Excel software (for example) by
           default interpreted it as representing an exponential which was inconvenient. As a related
           aside, ACME tests are often not conducted in order and some planned tests are regularly not
           conducted at all. The latter results in additional letter gaps if the tests from a day are sorted
           alphabetically. However, ACME testing often begins with test A1, where the final digit begins
           with 1 and is increased from there with variant or repeat tests for the same letter.

           The basic data is in a CSV format, i.e., with comma-separated values, which can be opened by
           spreadsheet software such as Microsoft Excel. The first row is a header and provides a limited
           summary of the hardware and operational conditions. The header is explained in Section 10.1
           Metadata Header of ACME-DOC-010 Rev D, which begins on page 126.

           As an example, the header from 20190A1_data.csv includes the following information

           Note that the chamber pressure (PTA3 from this file) should be more accurately available
           from the CIR chamber calculator file discussed in section 4.C1. The ACME pressure
           transducers have not been calibrated in years, while the calibrations for the corresponding
           CIR pressure transducers are checked every 6 months.

           Additional conversion is required for the measurements of the gas flow rates found in second
           through fourth columns of the data file. By column (e.g., in Excel), the flow rates are for:
               B       MFCA1StaticMixerFlow            oxidizer (or inert) gas
               C       MFCA2BypassFlow                 nitrogen
               D       MFCA3FuelFlow                   fuel

           The ACME MFCs are Hastings HFC-D-302 with default standard temperature and pressures
           (STP) of 0 Celsius and 760 torr for computations of volumetric flow or velocity. It is very
           important to understand that slpm, i.e., standard liters per minute, is a measurement of the
           mass (or alternatively molar) flow rate which is independent of the actual temperature or
           pressure. This is discussed for example in the MFC manual, where chapter 9 (on page 39) is
           “Volumetric vs. Mass Flow.” Hastings’s online converter at https://massflowconverter.com/
           may be helpful as a check in this regard.

       2. Mass Flow Controller (MFC) Setpoint File
          While the basic data file includes measurement of the gas flow rates, it may be helpful to

       4. Space Acceleration Measurement System (SAMS) data
          The Combustion Integrated Rack (CIR) in which the experiment was conducted, was equipped
          with a Passive Rack Isolation System (PaRIS), but it was not utilized for ACME testing because
          of the need for crew time to enable and disable the isolation (by respectively removing and
          installing alignment guides) on each test day. However, the CIR was equipped with a 3-axis
          SAMS sensor head. The acceleration archives, along with relevant documentation, are
          accessible from https://gipoc.grc.nasa.gov/wp/pims/home/, the home page for the Principal
          Investigator Microgravity Services (PIMS).

           The following guidance for the SAMS data was provided by Kenneth Hrovat (NASA Glenn): In
           addition to the documentation and links from the PIMS home page, we introduce a few ways
           below to get started with exploring the CIR microgravity environment taking the perspective
           of SAMS measurements from within the rack.

           Roadmap Spectrograms
           To get a high-level, spectral roadmap view within two days after measurement, you can:
               a. Use your browser and start at this link: http://pims.grc.nasa.gov/roadmap
               b. In the upper left pane, you can navigate by GMT date to see a list of plots (PDF files)
                   in the right pane for the GMT date of your choice. We refer to these PDFs as roadmap
                   plots. For SAMS, these are acceleration spectrograms, which for vibratory data are a
                   good way to look at patterns, structures and boundaries in both time and frequency
                   for long time spans -- nominally, 8 hours per plot. These spectrograms are mostly
                   qualitative and crudely quantitative three-dimensional plots in that a color scale
                   attempts to map power spectral density magnitude as a color for the 3rd dimension.
                   NOTE: Ticking the Navigation Filter for “es05” in the bottom pane will then only
                   highlight days in yellow in the upper left pane when the operations team powered on
                   the SAMS sensor in the CIR to take measurements.
               c. You might want to navigate directly to a GMT day of interest for your science
                   operations or run, but you can also browse day-by-day too in order to get some
                   context comparing various 8-hour spans to get a feel for the environment under
                   various conditions.

   B. Image Files
       Image data and files discussed in this section are associated with the following cameras:
              Analog, operations (ops), internal camera
              ACME Data Camera (DataCam)
              Cool Flames Investigation (CFI) intensified camera
              Low Light Level Ultraviolet (LLL-UV) camera
              High Bit-depth Multi-spectral (HiBMs) camera and CIR illumination package

       1. Analog, internal, operations (ops) camera
          This color analog camera is mounted on the ACME chamber insert, and as such is within the
          combustion chamber and is sometimes referred to as the internal camera. Its primary
          purpose is to support the operations, e.g., to visualize the burner and igniter, and as such is
          also often referred to as the operations or ops camera.

           The NTSC video (named for the National Television System Committee) from the ops camera
           is at 29.97 frames per second (fps) or nominally 30 fps. It is not recorded on the space station
           but is streamed to the ground in near real time and is recorded on CIR consoles at the Glenn
           ISS Payload Operations Center (GIPOC) in a Transport Stream (TS) format using VLC Media
           Player which can be freely downloaded from https://www.videolan.org/vlc/. That software
           has a snapshot function allowing for convenient extraction of still images, e.g., for making
           measurements of flame dimensions.

       2. ACME Data Camera (DataCam)
          ACME’s primary camera is a high-definition (1360 x 1024), 12-bit color camera mounted
          outside the chamber on CIR’s optical bench. It is equipped with a motorized lens with
          independent control of the zoom, iris, and focus. It has a filter barrel with a fused silica
          window (for color imaging), a blue-green BG7 Schott glass filter, and bandpass filters for
          imaging CH* and CH2O (formaldehyde) chemiluminescence.

           It was characterized prior to launch to enable temperature measurements via soot pyrometry
           and Thin Filament Pyrometry (TFP), soot volume fraction, and quantitative determination of
           the CH* concentration. However, the flames in s-Flame testing were soot-free with the

               198-206 (2016). https://doi.org/10.1016/j.combustflame.2016.02.012

           Images are normally downlinked within a week of the testing, but selected images are often
           downlinked during a test day. Regardless, the images are downloaded in a wrapped Halcon
           object (HOBJ) format, which is not readily opened with typical image processing software.
           The image data was made available in that raw format and later in a converted TIFF format,
           where the NASA conversion was carried out without each of the following:
                • color balancing (to avoid possible saturation as subsequently discussed)
                • dark frame subtraction
                • removal of hot spots from dead pixels (e.g., resulting from radiation damage)
           Furthermore, the NASA conversion employs a standard bilinear demosaicing process which is
           detrimental when determining temperature profiles via Thin Filament Pyrometry (TFP) as it
           will average pixels both on and off the glowing fibers. The priority in the NASA conversion
           was to make the images more readily accessible, not to meet all needs.

           Most ACME investigators are processing the raw HOBJ files using the OMA2 software
           developed by Prof. Marshall Long (Yale U.), the lead for ACME’s CLD Flame experiment. The
           OMA2 software is freely available in both Mac and cross-platform (Qt) versions, where the
           latter can be used with both PC and Linux operating systems. A tutorial was prepared by Dr.
           Jesse Tinajero on the use of OMA2 to process ACME’s HOBJ image files, where it can be found
           at https://www.youtube.com/watch?v=RMtu3KEXNiI. It has also been broken up and posted
           in three parts in which the image resolution may be better:
                Part 1 https://www.youtube.com/watch?v=kdQHeQwokvY
                Part 2 https://www.youtube.com/watch?v=Mua_8CfqhfM
                Part 3 https://www.youtube.com/watch?v=BGRqgbIxZL4

           The OMA2 read-hobj function was also rewritten by Tinajero as a Python function, where
           Python is an open source programming language that is easily obtainable for MacOS, Linux,
           and Windows operating systems. The Python script to open the HOBJ files can be downloaded
           from https://github.com/mblong/hobjExample. A tutorial for this function may be found at

           https://www.youtube.com/watch?v=4wbgWeJSilc.

           The HOBJ files can also be readily viewed and processed using ImageJ or its preloaded Fiji
           variant, where both can be freely downloaded. In either software package, the HOBJ files can
           imported (rather than opened) as raw files with the following settings:
                             Image type       16-bit unsigned
                                    Width     1360

                    Offset to first image     6244
           However, imported DataCam images will be monochrome unless a Bayer filter (e.g., as
           described at https://en.wikipedia.org/wiki/Bayer_filter) is subsequently implemented. It
           should be possible to install a plug-in to accomplish that color conversion. As another option,
           Python and Matlab both have image demosaicing functions.

           To use the ACME DataCam for quantitative measurements, it is critical to avoid saturation,
           for example by using a camera gain of zero. Another employed approach was to not use the
           camera’s white balance which by default multiplies the red and blue by 1.41 and 1.68,
           respectively, because that could inadvertently lead to saturation. Such multiplication can be
           done after the HOBJ file is converted and the colors demosaiced, where in OMA2 the white
           balancing is accomplished with the commands:
               *rgb 1.41 1 1.68
               clip 4095
           In summary, the white balance, if desired, needs to be done after the fact through software
           because it was at least generally not done with the hardware to avoid the risk of saturation.

           However, in carrying out color-ratio pyrometry calculations for the ISS data from ACME’s CLD
           Flame experiment, the investigators determined that the three color ratios (e.g., blue/red)
           didn’t result in the same temperature profile until the green channel was adjusted by 10%.
           This notably differs from the camera’s default of multiplication by 1 (i.e., no multiplication)
           for the green color plane.

           For Thin Filament Pyrometry (TFP): “After rigorous testing, it was determined [by Tinajero and
           Long] that a modified version of the bilinear method could be used to optimize the conversion
           of raw fiber images to full resolution color images. This modified version biases the linear
           interpolation along the length of the fiber. This method combined with moderate use of
           defocusing was found to reduce artifacts created by standard demosaicing algorithms and
           was used in all of the fiber measurements described below.”
               Jesse Tinajero and Marshall Long. “Dilution Limits of Coflow Laminar Methane and
               Ethylene Flames in Microgravity Versus Normal Gravity,” 12th U.S. National Combustion
               Meeting, 24-26 May 2021.

           Note that the ACME images will be naturally dark because of the use of the 16-bit file format
           with 12-bit image data. As such, adjustments to the image brightness will generally be
           necessary even if the images are not demosaiced. Furthermore, cameras’ CCD arrays are
           susceptible to radiation damage while in orbit. As a result, the images feature hot pixels which
           increase in number over the months and years in space. As such, it will appear as if there is a
           star field within the combustion chamber. Therefore, the images should ideally be processed

                                                   13
ACME/s-Flame Data Interpretation                                                       20 September 2021


           to remove the bright outlying hot spots. Radiation damage is also obvious in the ops camera
           imaging.

           Although the DataCam was typically set for imaging at 30 fps, that is trumped by the exposure
           settings which were often long because of the dim nature of the microgravity flames. As a
           result, the framing rate was typically far less. Different exposures are often selected for
           different phases of the tests, e.g., prior to ignition and during the test, so the framing rate
           may not be consistent. Bracketed imaging could also be employed, where a repeating
           sequence of different exposure durations is used to enable appropriate photography under
           uncertain or varying flame intensities. Bracketing can also used to simultaneously accomplish
           multiple imaging objectives, e.g., to appropriately image both brightly glowing soot (or TFP
           fibers) as well as the much dimmer blue portion of the flame.

           In interpreting the image data, it may be helpful to check the ACME DataCam metadata file
           which should be available for each successful flame test, e.g., to verify the exposure duration.
           These files are in a comma-delimited (CSV) format and can be opened with spreadsheet
           software or alternately as a text file. Column headings are found in the first row of such files.

           Due to the use of a turning mirror, the DataCam images should be flipped vertically if upright
           images are desired, i.e., where the burner is at the bottom and the flame extends upward. In
           this regard, note that the DataCam provides images in a ‘landscape’ format with the image’s
           long dimension orthogonal to the burner and chamber axis. This is contrary to an ACME
           science requirement specifying that the long dimension be aligned with the experimental axis
           to provide images in a ‘portrait’ format. In this regard, the science requirements were not
           always met, e.g., because of design tradeoffs.

           There is some variation in the ACME camera zoom, where its setting is not completely
           reproducible. Therefore, the scaling of the image data should ideally be established for each
           subset of tests if more than one zoom setting was used within a test day. The scaling can
           typically be carried out using images regularly taken of the ceramic fibers for Thin Filament
           Pyrometry (TFP), where such imaging is normally made at two fiber array positions.
           Meanwhile, the other cameras used in ACME testing had fixed lenses.

       3. Cool Flames Investigation (CFI) intensified camera
          This intensified camera was typically configured with a CH* bandpass filter and was generally
          archived at 23 fps. However, s-Flame tests were sometimes instead conducted with a
          formaldehyde (CH2O) filter or a clear fused-silica filter in the case of the hydrogen flames in
          the second-round testing (i.e., with helium dilution). The filter is normally identified in files
          with names such as 20190 test sheets.pdf.

           The grayscale image files are in a Tagged Image File Format (TIFF) format and can be opened
           readily, where brightness/contrast adjustment may again be required.

           Note that this camera’s Field of View (FOV) is partially blocked by the arms of the fiber array
           for Thin Filament Pyrometry (TFP) when it is moved to position the fibers across the flame.

           As with the ACME DataCam, it might be useful to check the metadata for the CFI intensified
           camera, which is in a comma-delimited (CSV) format and can be opened with spreadsheet
           software or alternately as a text file.

       4. Low Light Level Ultraviolet (LLL-UV) camera
          This monochrome camera has an intensifier (for 280-700 nm) and a 310-nm bandpass filter
          (with a 10-nm FWHM) for OH* imaging. As a result of the signal loss through the filter, binning
          is employed such that the OH* images are recorded at 512x512 and 30 fps. After post-
          processing on the ground, the grayscale image files are available in a Tagged Image File
          Format (TIFF) format and can be opened readily, where brightness/contrast adjustment may
          be required.

           Like the CFI intensified camera, the LLL-UV camera’s Field of View (FOV) is partially blocked
           by the arms of the fiber array for Thin Filament Pyrometry (TFP) when it is moved to position
           the fibers across the flame.

           While the LLL-UV camera was used throughout s-Flame testing, it wasn’t used at all for the
           other five ACME experiments.

       5. High Bit-depth Multi-spectral (HiBMs) camera and CIR illumination package
          The HiBMs camera was used in combination with an opposed backlight, i.e., the CIR’s
          collimated illumination package. The resultant imaging was used in preceding droplet
          combustion experiments for measuring droplet diameter, but it may also be useful for
          determining the soot volume fraction via light extinction. However, the camera’s red filter,
          corresponding to the red illumination, appears to be broad enough to permit significant soot
          incandescence to pass through the filter. As a result, this imaging is unlikely to be useful for
          soot volume fraction measurements for all conditions. After post-processing on the ground,
          the images were made available in the TIFF format and as such are readily opened. The
          grayscale images were typically archived at 15 fps.

           It is important to understand that this camera’s images are of little value for s-Flame because
           of the general lack of soot. However, there was sometimes soot seen during ignition.
           neglecting ignition in some cases. But even considering that, the soot volume fraction can be
           computed using images from the ACME DataCam as discussed in that camera’s section.

           In initial ACME testing with the Coflow Laminar Diffusion Flame (CLD Flame) experiment, this
           monochrome camera was used without a filter, but that was abandoned because the camera
           is nearly insensitive to blue. The red filter was installed on 5 March 2018 and used throughout
           all subsequent ACME testing.

       1. CIR chamber calculator file
          In great contrast to other file types, there is a single file, named ‘ACME Chamber Calculator -
          2018-03-08 to 2020-07-08.xlsx,’ which provides estimates of the composition of the
          combustion chamber before and after each s-Flame test (and during earlier testing), and more
          generally for every Fuel/Oxidizer Management Assembly (FOMA) action involving gas flow
          into or out of the chamber. As a result, this includes filling and venting operations, plus
          recirculation of the chamber contents through the adsorber cartridge filled with 13x
          molecular sieves.

           More specifically, the chamber calculator provides the chamber pressure before and after
           each operation involving flow into or out of the chamber. While the standard ACME data
           output files (discussed in section 4.A.1) provide the chamber pressure throughout each test,
           that measurement is from a pressure transducer that hasn’t been calibrated in years.
           Meanwhile, the calibrations of the corresponding CIR pressure transducers are checked every
           six months and if needed those calibrations are updated. Therefore, the chamber calculator
           is the more reliable source of the chamber pressure.

           The pressure in the CIR chamber is measured by four different CIR pressure transducers, of
           which one (PT29) is a different model used for safety. The output of the other three
           transducers were used to obtain an average chamber pressure. However, the output of one
           of those (PT28) was clearly an outlier from the other two (PT16 and PT17) as well that of PT29.
           Therefore, the average pressure recorded in the chamber calculator file was later based on
           just PT16 and PT17.

           For s-Flame, the chamber calculator also provides concentration estimates of the following
           gases within the chamber before and after each test and FOMA operation:
               Oxygen & inerts:        O2, N2, He
               Fuels:                  H2, CH2, C2H4
               Combustion products: CO2, H2O
           The latter are based on telemetry from the three Mass Flow Controllers (MFCs) on the ACME
           chamber insert for the flow of fuel, oxygen (or inert), and nitrogen.

           In a test, the chamber calculator assumes either complete combustion or no combustion,
           where in the former case the reactant flowing from the burner is transformed into carbon
           dioxide and water vapor (or water vapor alone if the fuel was hydrogen). While failed or
           unsustained ignitions were typically set to assume no ignition. Short-lived flames were often
           treated as having complete combustion, even if a significant fraction of the reactant didn’t
           burn. As such, the chamber calculator has its limitations.

           With recirculation of the chamber contents, the calculator assumed that the carbon dioxide
           and water vapor were completely adsorbed, i.e., removed from the chamber. Meanwhile, it
           assumes that any unburnt fuels – hydrogen, methane. and ethylene - are not adsorbed.

           In Aug. 2021, it was determined that the ACME chamber calculator doesn’t account for gas
           conversion factors where the Mass Flow Controllers (MFCs) were calibrated for nitrogen. This
           shortcoming can affect the results significantly. As an example, the conversion factor for
           ethylene - the most commonly used ACME fuel - is nominally 0.6 which is quite different from

                                                  19
ACME/s-Flame Data Interpretation                                                     20 September 2021


           1. See section 4.A.1 of this document for additional information about this conversion.

           At the time of this writing, NASA is working on improvements to the chamber calculator file,
           but researchers can of course make their estimates of the chamber contents where the
           chamber calculator should nonetheless be referenced for its record of fills, venting, and

       2. Test parameter file
          Each s-Flame test was controlled by a software script and corresponding parameter file,
          named for example ‘as run20176B1.txt,’ specifying settings for imaging, ignition, gas flow, and
          more. The parameter file and script are discussed extensively in the ACME/s-Flame
          Experimental Procedure document, which should be referred to for information on this file
          type. But note that the ACME.log files should be the best way to verify the as-run test
          parameters, where the separate parameter files are unfortunately not completely reliable.
          They have not always been saved and when the file saving was automated, they have still
          sometimes had missing entries.

       3. Notes
          Notes of various types are available for test days, where not all types were collected or
          necessarily prepared for each test day. It is important to understand that the notes, whether
          handwritten or typed, may include mistakes. It is better to rely on automated logs, metadata
          files, and parameter files or of course the measurements themselves when possible.

           The daily test point logs, with names such as ‘19254 daily test point log.pdf,’ chronologically
           list the tests and the image data acquired which was to be downlinked. Typically, image data
           was not downlinked without successful, i.e., sustained, ignition. As an example, image data
           wasn’t downlinked if the test aborted prior to ignition. However, the reverse is not always
           true. Image data was sometimes downlinked when ignition was unsuccessful and as a result
           the test point log is only a clue as to what transpired. Furthermore, note that image data
           from certain selected cameras, e.g., the HiBMs camera, was sometimes not downlinked due
           to the limit of how much data could be reasonably downlinked in a subsequent two-shift day.

           Notes with names such as ‘19254 flow traces etc.pdf’ include preliminary plots of the flow
           rates (as seen on a console during testing) and other flame diagnostics, typically along with
           additional information about the tests.

           The test parameter notes, with names such as ‘19254 test parameter notes.pdf,’ show the
           parameter values which were planned in advance of the test day and the changes made
           during the test day.

           The test sheets, with names such as ‘19254 test sheets.pdf,’ are summary notes about the
           conduct of each tests conducted that day.

Appendix A
Nomenclature
This document’s key abbreviations are listed here.
ACME           Advanced Combustion via Microgravity Experiments (project including s- Flame)
AOI            Area of Interest (e.g., for image acquisition of just a portion of the camera FOV)
ASCII          American Standard Code for Information Interchange
BRE            Burning Rate Emulator (another ACME experiment)
CCD            Charge-Coupled Device (such as a camera sensor)
CIR            Combustion Integrated Rack (ISS facility in which ACME experiments are conducted)
CFI            Cool Flames Investigation (a droplet combustion experiment preceding ACME in the CIR)
CLD Flame      Coflow Laminar Diffusion Flame (another ACME experiment)
CSV            comma-separated values
DataCam        Data Camera (for ACME experiments, characterized for pyrometry, etc.)
E-FIELD Flames Electric-Field Effects on Laminar Diffusion Flames
Fiji           Fiji Is Just ImageJ (a version of ImageJ preloaded with many plug-in features)
FOMA           Fuel Oxidizer Management Assembly (CIR’s gas management subsystem)
FOV            Field of View
fps            frames per second
GCIP           Gas Chromatograph Instrumentation Package
GIPOC          Glenn ISS Payload Operations Center
GMT            Greenwich Mean Time
HiBMs          High Bit-depth Multi-spectral camera (of the CIR facility)
HOBJ           Halcon object (binary uncompressed format; used for the DataCam)
ImageJ         Image Processing and Analysis in Java (open-source image processing software)
IPSU           Image Processing and Storage Unit (CIR subsystem)
IPSU-G         IPSU for Gigabit ethernet cameras
ISS            International Space Station
LLL-UV         Low Light Level Ultraviolet camera (of the CIR facility)
MFC            Mass Flow Controller
NTSC           National Television System Committee
OMA2           Optical Multi-channel Analyzer 2 (open-source software for image processing and display)
ops            operations
PaRIS          Passive Rack Isolation System
PIMS           Principal Investigator Microgravity Services
PMT            Photomultiplier Tube (where ACME is equipped with three PMT modules)
PT             pressure transducer
psia           pounds per square inch
s-Flame        Structure and Response of Spherical Diffusion Flame (another ACME experiment)
SAMS           Space Acceleration Measurement System
slpm           standard liters per minute (a measure of the mass or molar flow rate of a gas)
TFP            Thin-Filament Pyrometry (a technique for making gas-phase temperature measurements)
TIFF or TIF    Tagged Image File Format (used by the CFI, HiBMs, and LLL-UV cameras)
TM             thermistor
TS             Transport Stream (a video format)

Installation of QtOMA2 on a PC
        These instructions were provided by Prof. Marshall Long (Yale U.).

These instructions assume you don’t already have Qt installed. If you do, skip to Part B.

Part A:
Download the opensource Qt from https://www.qt.io/download.
➔ Go open source
➔ Download the Qt Online Installer
➔ Download
➔ Save File


In the downloads folder, open qt-unified-windows-x86-x.x.x-online
➔ Sign up for a Qt account or login
➔ Accept Open Source obligations
➔ Contribute to Qt Development (on not)
➔ Accept default install location
➔ Install the components as shown in the figure on the next page
➔ Agree to terms
➔ Add shortcuts
➔ Install


Part B:
Download the latest version of QtOma2 from https://github.com/mblong/qtoma2.
➔ Code → Download ZIP

Expand the zip file.
In the qtoma2-master folder, open QtOma.pro (the Qt Project file)

The first time this opens in Qt Creator, it will ask for the project to be configured. Just choose the
defaults.

➔ Configure Project
➔ In the lower left corner, click on the green arrow to run QtOma2.

1.0 INTRODUCTION
Smoke Aerosol Measurement Experiment (SAME) is an experiment payload planned for the Microgravity Science
Glovebox (MSG) located on the International Space Station (ISS). The Crew Display (a.k.a. Human-Computer
Interface or HCI) will operate on the MSG Laptop Computer MLC. It provides the crew with information about the
current status of the experiment and an ability to issue commands to control the system.
The crew interface for SAME is intended to be used only in off-nominal conditions. The nominal operation of the
experiment will occur via ground commanding.

1.1     Purpose
The purpose of this document is to describe the SAME Crew Display and to:

      1) Provide details about the implementation of the SAME Crew Display requirements found in SAME-DOC-
         004, Section 7.0
      2) Satisfy the Preliminary and Candidate Display Deliveries as required for the Payload Display Review Team
         (PDRT)

1.2     Scope
This document is limited to the operation of the SAME Crew Display. Issues concerning general operation of the
experiment via the software operating on the DACU or ground systems are not discussed here.

2.0 CREW INTERFACE
2.1       Purpose
The purpose of the crew interface on SAME is to provide some basic information about the status of the experiment
during off-nominal conditions, especially in case of loss of data telemetry and/or commanding from and to the
ground. This information is minimal in nature. It represents the basic information that a crew member may be
asked to report and commands they are asked to issue during off-nominal conditions.
Section 3.0 provides flow diagrams showing the typical use of the crew interface. In summary, those uses are:
      •    Commanding and Telemetry Check. Verification of SAME data transmittal and command reception.
      •    Sample Positioning Check. Used to debug unexpected sample positioning behavior that could use a crew
           member’s eye.
      •    Gate Valve Check. Used to debug unexpected gate valve behavior.
      •    P-Trak Configure. Execute specified commands and verify specified results on the P-Trak to achieve
           reconfiguration and/or debugging.
      •    Commercial Diagnostics Configure. Execute specified commands and verify specified results on the
           Commercial Diagnostics unit to achieve reconfiguration and/or debugging.
      •    Attended Operations. Ability to power-up the SAME DACU, initialize the instrument, run a specified
           test, and shut down.

2.2.3 Payload Status Area
This is an area reserved in the DGCS for payloads to present critical information that is shown at all times. SAME
will use this area to display information about the experiment and testing status.
The Run Mode field displays the current running status of the SAME experiment. Possible values are:
               STARTUP     The DACU software is starting
             UNINITIALIZED The DACU software is waiting for the System Initialize command
               STANDBY     The DACU software has been successfully initialized and is waiting for
                           commands and is emitting housekeeping data.
             TEST RUNNING A test is currently in progress
             TEST PAUSED A test is paused
              SHUTDOWN The DACU software is in the process of shutting down.
                                        Table 2 - Run Mode Values

The OK Status indicator replicates the physical LED labeled OK on the DACU housing. It represents the physical
status of the experiment. When the indicator is lit the system is operational (e,g, powered, booted, ready to run);
unlit indicates the system is not operational (e.g. not powered, in error).

The Test Number field displays the current test number the DACU is running or prepared to run.

The Elapsed Time field displays how long the current test has been running (HH:MM:SS). If no test is running the
field will be blank

The GPS field is required by SSP50313. It provides a time reference for payload operations.

2.2.5 Workspace
The workspace area is used for displaying information and controls for a given function. The contents will change
based on the primary function selected.

2.2.5.1 Welcome Screen
The welcome screen is the first thing displayed when the crew display is started. There is no real content display, but
it serves the purpose of positively identifying the SAME experiment. Once the operator selects a function from the
primary button panel, the workspace will change to the new display. There is no way of displaying the welcome
screen again without exiting and restarting the program.

2.2.5.2 Status Screen
The summary status display is shown when the operator presses the Status button. It shows information about the
state of SAME in addition to what is shown in the Payload Status Area (see 2.2.3).




                                             Figure 3 - Status Screen


2.2.5.2.1 Sample Positioning Group
The sample group consists of 3 fields. The Sample Number field is the number of the sample within the carousel
being tested at that time. The Carousel Number field is the number of the carousel that is installed. A carousel
holds six samples. The combination of the carousel and sample number uniquely identifies a particular test item. The
Resistance field displays the measured resistance of the heater wire coil for the sample. This is used as a unique
physical indicator of which sample is being tested.
2.2.5.2.2 SAME Power Group
MSG provides SAME with 120VDC. SAME converts this into 5 separate voltages using DC/DC converters. The
SAME Power group consists of fields indicating the state of the 5 voltages. For all voltages, the possible state
include ON and OFF. In addtion the 12 VDC Heater, 12 VDC Misc, and 5 VDC can have a state of Enabled, which
means that it was turned on, but has not yet been sensed as on.
2.2.5.2.3 Ethernet Switch Group
The MLC Ethernet connection is routed through a switch inside SAME. The switch connects the MLC to either the
ISS LAN Backbone or to the SAME DACU. The purpose of this is to allow the DACU to transfer data files to the
MLC via FTP. The switch is nominally controlled by the DACU; however the crew can manually activate the switch
if necessary. When the DACU is unpowered, the switch connects the MLC to the ISS LAN. The Ethernet Switch
group reports the state of the switch. There are three possible values:

2.2.5.2.4 Gate Valves Group
The Gate Valves group displays the status of two valves; the Inlet and Outlet valves. These can either be OPEN or
CLOSED.
2.2.5.2.5 Supply Group
SAME uses the GN2 and vacuum resources supplied by MSG. SAME regulates the GN2 supply as needed. The
Supply Group displays the status of these gas supplies and the vacuum state. The Main GN2 and Main Vacuum
resources both have valves that are controlled by the DACU. The valve indicator fields show the state of these
valves; OPEN or CLOSED. The pressure of the main GN2 supply, the vacuum, and the regulated GN2 are
reported.

2.2.6 Log
The message log lists all the messages that have been received or generated by the interface. Messages originate
from two sources: the DACU and the interface itself. The latest DACU message also appears on the Status Bar (see
2.2.4). By default messages are sorted by GPS with the latest messages at the top. The window may be scrolled to
see earlier messages. Sorting order and column can be changed by selecting the column heading. Sub-sorts are
achieved by holding <CTRL> while selecting two or more headings. An arrow in the heading indicates whether
sorting is by decreasing (down arrow) or increasing (up arrow) order.

Messages appear in the list with three pieces of information. First is the GPS timestamp of the message. Second is a
Level indicator. Messages are assigned one of the following levels: INFO, ERROR, or CONFIG. The final piece of
information is the message description itself.

Messages that originated from the DACU are always assigned an INFO or ERROR level. The DACU message is
then summarized in a single text string with all the individual message fields identified. Messages originating from
the interface can be CONFIG or ERROR level.
